## What is queued

`tuning/control/vast-l40s-53735.json` builds two cores at 29ac5f5 and switches no GPU:

- `rule`: no defines. The host picks Ada's batch width from the L2 the card reports
  (29ac5f5): 2048 if col_batch x 16 x k plus a band of A' fits (72 MB or more), else 1024
  on 48-64 MB.
- `cb1024`: `-DPEARL_ADA_COL_BATCH=1024u`, the width forced to 1024.

The test this was for: g1 on `rule`, g2 on `cb1024`, g0 and g3 on the release, over the
same minutes, after a release baseline. It answers two things on an L40S:

1. Which width the rule picks. Nothing on the box prints `cudaDevAttrL2CacheSize`. The
   South Africa notes say 48 MB, but AD102 spec sheets list 96 MB for the L40S. If `rule`
   runs level with the release, it kept 2048 (the card reports 72 MB or more). If it runs
   level with `cb1024`, it picked 1024.
2. Whether 1024 beats 2048 here. The L40S is power-capped at 350 W like the 4070 Super,
   where 1024 gave +2.5 to +3.1% (116195). If the L2 is 96 MB, the 70 MB working set at
   2048 should mostly stay in the L2 and the gain should be smaller.
