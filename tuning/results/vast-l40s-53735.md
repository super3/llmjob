## What is queued

`tuning/control/vast-l40s-53735.json` builds two cores and switches no GPU:

- `rulelog`: 17d80bc with `-DPEARL_LOG_ADA_L2=1`. The host picks Ada's batch width from
  the L2 the card reports (the rule from 29ac5f5): 2048 if col_batch x 16 x k plus a band
  of A' fits (72 MB or more), else 1024 on 48-64 MB. The define only adds one startup line,
  `[pearl] Ada fold: L2 <bytes> (<MB>), col_batch <n>`, which shows in `[minerlog]`.
- `cb1024`: 29ac5f5 with `-DPEARL_ADA_COL_BATCH=1024u`, the width forced to 1024.

The test this was for: g1 on `rulelog`, g2 on `cb1024`, g0 and g3 on the release, over
the same minutes, after a release baseline. It answers two things on an L40S:

1. Which width the rule picks. The South Africa notes say 48 MB of L2, but AD102 spec
   sheets list 96 MB for the L40S. `rulelog`'s startup line settles it.
2. Whether 1024 beats 2048 here. The L40S is power-capped at 350 W like the 4070 Super,
   where 1024 gave +2.5 to +3.1% (116195). If the L2 is 96 MB, the 70 MB working set at
   2048 should mostly stay in the L2 and the gain should be smaller.
