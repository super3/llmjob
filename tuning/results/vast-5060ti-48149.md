## Baseline

never have built a core. box.sh should run `dpkg --configure -a` before each `apt-get`.

## Static checks of sm_120 compile-time settings

The cores this harness builds on a box come from nvcc 12.8. The release loads its CUDA 13
core on Blackwell with a 580+ driver. To see what a 12.8 build can tell us about the CUDA 13
core, I compiled `pearl_kernel.cu` for sm_120 locally with nvcc 12.8.93 and 13.3.73 (NVIDIA's
redist and PyPI packages) and counted the tall fold's chunk loop in the SASS.

| Build | Registers | Spill (stores/loads) | Chunk loop instructions | IMMA with B `.reuse` |
|---|---|---|---|---|
| 13.3, defaults (the cu13 core) | 254 | 0 / 0 | 469 | 160 of 192 |
| 12.8, defaults (the cu12 core) | 254 | 0 / 0 | 635 | 0 of 192 |
| 12.8 front end, ptxas 13.3 | 254 | 0 / 0 | 465 | 160 of 192 |

- Under 12.8 every IMMA is followed by a NOP and a 15-cycle stall (173 NOPs a chunk) and no
  IMMA reuses B. ptxas 12.8 schedules the loop in a different way altogether, so a ring or
  fence setting measured on a 12.8 build on a box says nothing about the CUDA 13 core.
- The whole gap is ptxas: the 12.8 front end's PTX assembled by ptxas 13.3 matches the
  13.3 build. Finland (149979) measured the runtime gap on this card: cu12 is 2.9% slower.
- Under 13.3, none of the sm_120 ring and fence switches moves the loop by more than 4
  instructions: `PEARL_TALL_TMA_FILL_PT` 8, 12 and 16, `PEARL_TALL_TMA_EMPTY_ALL`, both
  together, `PEARL_TALL_TMA_PRODUCER2`, `PEARL_TALL_STAGE_FENCE` 0/1/2,
  `PEARL_TALL_PREGUARD` 0 and fence mask 0 all land at 465-470, with no spill (mask 0 loses
  B reuse). Under 12.8 the same switches stay at 622-655 with no B reuse.
- `PEARL_TALL_CLUSTER=1` (the two-CTA B multicast) spills under both compilers (13.3: 255
  registers, 176/228 bytes, loop 586). The spill comes from the multicast itself: the same
  build with a plain B load fits (254 registers, no spill, loop 478). Its cluster-scope
  arrive and wait also put two `MEMBAR.ALL.GPU` on every EMPTY arrive; CUTLASS's default
  (CTA) scope removes them (loop 560) but not the spill.

So no sm_120 compile-time switch is worth a runtime slot at the 1% bar.
