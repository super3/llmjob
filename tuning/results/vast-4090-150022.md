# vast-4090-150022: RTX 4090 x1, North Carolina (Vast machine 150022, spot)

Ada, compute 8.9, driver 610.57.04, 450 W power limit, max SM clock 3105 MHz. v0.5.12
release, one miner. The release core on Ada is cu12: `coreVariant.js` picks cu13 on its
own only for compute 12.x, even with a 580+ driver.

This card is held back by heat, not by its power limit: it sits at 90 C and about 2205 MHz
while drawing about 358 W of its 450 W. So any change that saves energy per hash should show
up as clock here.

## Harness bug found here

`box.sh` starts a miner with `( cd $R && env ... ./cli ... & echo $! > g0.pid )`. `$!` there is
a wrapper bash, not the cli, so `stop_gpu` kills only the wrapper and the old miner keeps
mining. Every settings change adds one more miner on that GPU. Reproduced locally: the pid file
named a bash process, and its child kept running after the kill. The fix is `exec env ...` in
the subshell, so that `$!` is the cli itself. Running boxes keep the script they were rented
with, so they need the fixed script and a restart before any switch can be measured. A
container restart clears the orphans (the main session restarted this box at 09:04), and the
box resumes on its saved control file. The fixed script is ce1d7c9 on this branch; only boxes
started after 09:04:15 UTC run it. This box still runs the old one, so its control file stays
on cu13 and it takes no more switches until it is moved to the fixed script.

## Offline checks (sm_89, no GPU)

Compiled locally with nvcc 12.8.93, the compiler of the release's cu12 core and of on-box
builds, and read the SASS with cuobjdump.

- The v0.5.12 release `pearl_core.node` (cu12), sm_89 cubin: `pearl_tile_fold_tall` is the same
  as a local build of this branch, instruction for instruction (3040 of 3040). With 149491's
  check that cu13 builds the same fold, an on-box build with no defines is the release on Ada.
  So Ada builds can be judged against the release directly.
- Compiler flags do nothing to the fold: `--extra-device-vectorization`,
  `-Xptxas --allow-expensive-optimizations=true` and `-Xptxas -O2` leave its SASS identical.
